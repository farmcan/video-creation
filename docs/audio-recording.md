# 本机系统声录制与验收

2026-11-18；复用这次已走通的 QuickTime 回环录音。适用于用户已授权录制、且平台允许播放的音频；录音文件是播放输出，不是平台导出的母带。具体曲目和路径见 [本次素材索引](../projects/jensen-song-2026-11-17/LOCAL-ASSETS.md)，实测证据见 [播放验收记录](../projects/jensen-song-2026-11-17/PLAYBACK-QA-20261118.md)。换主题时沿用流程，重新核对设备与权限。

## 最短执行流程

1. **记下原设置。** 记录系统输出、音量和静音状态。确认同一曲目／版本、全曲长度及正常播放入口；不要因卡顿重复生成歌曲。
2. **接通系统声回环。** 本机成功配置是系统输出选已有“多输出设备”（Filmage Audio Device + MacBook Pro 扬声器），QuickTime Player → 新建音频录制 → 输入选 Filmage Audio Device。保留扬声器供人试听；不要选环境麦克风，不沿用旧 UI 元素编号。
3. **先录短样本。** 正常点击播放器 Play，录 10–20 秒后保存、检查录音是否有信号。录音计时增长不能证明录到了声音。若选 BlackHole 作录音输入，系统输出也必须实际路由进 BlackHole；本次只选输入、系统仍输出扬声器时得到全静音。
4. **再从曲首录全曲。** 重载同一曲目，先开始录音再点击 Play。观察前、中、后段播放器进度与录音电平，直到自然结束再停止。若浏览器停在固定时间，先复测同一曲目的独立页面；本次 Chrome 约 27 秒卡住，独立 in-app browser 同一曲目成功播完。该对照只证明存在页面差异，具体网络根因仍未知。
5. **保存与恢复。** 原录音保存在仓库外私有目录，保留原件；恢复先前输出／音量／静音状态。本次结束后恢复 MacBook Pro 扬声器、音量 50%、未静音。
6. **验连续性，再验内容。** 检查时长、首尾和内部静音，裁去录制准备／结束后的空白，保留音乐首尾缓冲。可转换兼容试听格式；记录裁剪参数、文件哈希及工具版本。没有听完不能把“有声音”写成“唱词和旋律正确”。

## 可复用的本地命令

已有 `ffmpeg` / `ffprobe` 可检查；下列路径是占位符，执行前替换，不覆盖原录音。

```sh
ffprobe -v error -show_entries format=duration,size -show_entries stream=codec_name,sample_rate,channels -of json recording.m4a
ffmpeg -hide_banner -i recording.m4a -af silencedetect=noise=-60dB:d=0.5,volumedetect -f null -
shasum -a 256 recording.m4a
```

`silencedetect` 给出候选静音区间，需区分前后空白、曲内设计停顿和播放故障；其算法不等同于本次每 20 ms、跨声道 RMS 审计。立体声检查先按声道聚合能量，避免直接相加导致相位抵消。峰值接近 0 dBFS 提示检查增益和失真，不能反推源母带质量。

本次还用已有 `whisper-cli` 和 `tiny.en-q5_1` 做**无目标歌词提示**的英语转写，作为漏词／段落定位线索。歌唱、姓名、伴奏和拖音会误识别，必须回到声音核对；ASR 不验旋律，不因识别错误自动改词。

## 交付记录的最少字段

- 来源曲目／版本；网页时长、原录音时长、试听文件时长。
- 录音输出与输入设备；开始／结束观察；原设置是否已恢复。
- 原件和衍生文件路径、裁剪起点／长度、SHA-256。
- 内部异常静音与处理；已核段落；唱词、旋律、重音、听感各自状态。
- 尚未通过项及下一步；音频、完整 ASR、截图留私有目录，不入公开仓库。

## 本次会话失败教训

原会话在把 MP3 经工具 `audio()` 返回为 `input_audio` 后，紧接着出现 HTTP 400 `Audio input is not available`；随后纯文字轮次也连续失败。日志支持“音频工具结果触发失败、历史音频可能继续随上下文提交”的判断，未验证服务内部机制或原会话已修复。当前工作流使用本地文件播放器、音频分析和文本结果；不向当前不支持音频输入的模型注入音频。更换会话时读取本仓库文档和文件索引即可恢复任务，不依赖旧会话成功加载。
